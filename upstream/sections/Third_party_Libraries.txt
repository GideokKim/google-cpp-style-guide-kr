When choosing to use third-party libraries, be consistent with the code around you. A third-party library is a library that is not primarily developed in the same repository as your code. Reusing high-quality third-party libraries can avoid vast amounts of work duplicating their functionality. Some third-party libraries are so well-established in their problem domain that avoiding them would actually make the code harder to read. Third-party libraries may have different programming practices than ours. In some cases this can be "viral", making it harder for code that uses the library to follow our style and programming practices. Third-party libraries can carry many hidden support burdens, such as license compliance, monitoring and patching vulnerabilities, and dealing with breaking changes from upstream. When choosing a library to solve a particular problem, first check if there's already a library that your codebase typically uses for that kind of problem. If so, use it. If not, prefer libraries from the following sources, in roughly decreasing order of priority: Abseil . The C++ standard library (except as discussed here) Existing first-party libraries in the codebase. Third-party libraries If you choose to use a third-party library, make sure to follow your codebase's policies for third-party code.
