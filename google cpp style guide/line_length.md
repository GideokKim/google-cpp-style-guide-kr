# 줄 길이 (Line Length)

## 원문 규칙 번역

코드의 각 텍스트 줄 길이는 최대 80자여야 합니다.

이 규칙을 선호하는 사람들은 창 크기를 조정하도록 강요하는 것은 무례하며 더 이상 필요하지 않다고 주장합니다. 일부 사람들은 여러 개의 코드 창을 나란히 사용하는 데 익숙하므로 어떤 경우에도 창을 넓힐 공간이 없습니다. 사람들은 특정 최대 창 너비를 가정하여 작업 환경을 설정했으며, 기존 표준은 80열이었습니다. 왜 바꾸나요?

변화를 지지하는 사람들은 줄이 넓어지면 코드를 더 읽기 쉽게 만들 수 있다고 주장합니다. 80열 제한은 1960년대 메인프레임에 대한 숨은 후퇴입니다. 현대 장비에는 더 긴 줄을 쉽게 표시할 수 있는 넓은 화면이 있습니다.

최대 80자입니다.

다음과 같은 경우 한 줄이 80자를 초과할 수 있습니다.

- 가독성, 잘라내기 및 붙여넣기 용이성 또는 자동 링크를 손상시키지 않고 분할할 수 없는 주석 라인(예: 라인에 예제 명령 또는 80자를 초과하는 리터럴 URL이 포함된 경우)
- 80개 열로 쉽게 래핑할 수 없는 문자열 리터럴입니다. 이는 URI 또는 ​​기타 의미상 중요한 부분이 포함되어 있거나 리터럴에 내장된 언어가 포함되어 있거나 도움말 메시지와 같이 개행이 중요한 여러 줄 리터럴이기 때문일 수 있습니다. 이러한 경우 리터럴을 분할하면 가독성, 검색 가능성, 링크 클릭 기능 등이 감소합니다. 테스트 코드를 제외하고 이러한 리터럴은 파일 상단 근처의 네임스페이스 범위에 나타나야 합니다. Clang-Format과 같은 도구가 분할할 수 없는 콘텐츠를 인식하지 못하는 경우 필요에 따라 콘텐츠 주변의 도구를 비활성화하세요. (우리는 그러한 리터럴의 유용성/검색 가능성과 그 주변 코드의 가독성 사이의 균형을 맞춰야 합니다.)

## 이해하기 쉽게 설명하기

이 규칙의 핵심은 - 가독성, 잘라내기 및 붙여넣기 용이성 또는 자동 링크를 손상시키지 않고 분할할 수 없는 주석 라인(예: 라인에 예제 명령 또는 80자를 초과하는 리터럴 URL이 포함된 경우) - 80개 열로 쉽게 래핑할 수 없는 문자열 리터럴입니다.

실제로 코드를 볼 때는 이는 URI 또는 ​​기타 의미상 중요한 부분이 포함되어 있거나 리터럴에 내장된 언어가 포함되어 있거나 도움말 메시지와 같이 개행이 중요한 여러 줄 리터럴이기 때문일 수 있습니다.

점검할 때는 특히 다음을 확인하세요:

- 일부 사람들은 여러 개의 코드 창을 나란히 사용하는 데 익숙하므로 어떤 경우에도 창을 넓힐 공간이 없습니다.
- 이러한 경우 리터럴을 분할하면 가독성, 검색 가능성, 링크 클릭 기능 등이 감소합니다.
