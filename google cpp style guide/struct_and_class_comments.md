# 구조체와 클래스 주석 (Struct and Class Comments)

이 항목은 Google C++ 스타일 가이드의 `Struct and Class Comments` 규칙을 한국어로 정리한 것입니다. 핵심은 기능 자체를 사용할 수 있는지보다, 그 기능이 읽는 사람에게 얼마나 분명하고 안전하게 전달되는지를 기준으로 판단하는 것입니다.

다음 원칙을 따르세요:

- 주석은 코드가 말하지 못하는 의도, 이유, 제약을 설명해야 합니다.
- 무엇을 하는지는 코드가 보여 주고, 왜 그렇게 하는지는 주석이 보완합니다.
- 낡은 주석은 없는 주석보다 더 해로울 수 있으므로 코드와 함께 유지하세요.

규칙을 적용할 때는 현재 파일의 기존 스타일, 공개 API에 미치는 영향, 자동화 도구가 기대하는 형태를 함께 고려해야 합니다. 새 코드는 이 규칙을 직접 따르는 것을 기본으로 하고, 기존 코드는 관련 코드를 수정하는 자연스러운 시점에 함께 정리하는 것이 좋습니다.

---

## 이해하기 쉽게 설명하기

`구조체와 클래스 주석`는 코드를 작성하는 사람보다 나중에 읽고 고치는 사람을 위한 규칙입니다. 당장 작성하기 편한 표현이더라도 호출 지점, 선언 위치, 파일 구조를 읽는 사람이 숨은 의미를 추측해야 한다면 좋은 선택이 아닙니다.

실무에서는 다음 질문으로 판단하면 쉽습니다.

- 이 코드를 처음 보는 사람이 이름과 선언만 보고 의도를 이해할 수 있는가?
- 다른 파일이나 팀의 코드와 섞였을 때 충돌하거나 오해될 여지는 없는가?
- 더 단순한 언어 기능이나 더 명시적인 표현으로 같은 목적을 달성할 수 있는가?

이 질문에 명확히 답하기 어렵다면, 더 좁은 범위·더 분명한 이름·더 단순한 구조를 선택하는 편이 Google 스타일 가이드의 방향에 가깝습니다.
