# thread_local 변수 (thread_local Variables)

함수 안에 선언되지 않은 `thread_local` 변수는 진짜 컴파일 시간 상수로 초기화되어야 하며, 이를 `constinit` 속성으로 강제해야 합니다. 스레드별 데이터를 정의해야 한다면 다른 방법보다 `thread_local`을 선호하세요.

`thread_local` 변수는 다음처럼 선언할 수 있습니다.

```cpp
thread_local Foo foo = ...;
```

이 변수는 실제로 여러 객체의 모음입니다. 서로 다른 스레드가 접근하면 각자 다른 객체에 접근합니다. `thread_local` 변수는 여러 면에서 정적 저장 기간 변수와 비슷합니다. 네임스페이스 범위, 함수 안, 정적 클래스 멤버로 선언할 수 있지만 일반 데이터 멤버로는 선언할 수 없습니다.

함수 안의 `thread_local` 변수는 비교적 안전하지만, 그 밖의 `thread_local` 변수는 정적 변수와 같은 초기화 순서 문제와 추가적인 스레드 관련 문제를 가집니다. 또한 스레드 종료 시 `thread_local` 변수는 초기화의 반대 순서로 소멸합니다. 어떤 소멸자가 이미 파괴된 다른 `thread_local` 객체를 참조하면 진단하기 어려운 use-after-free가 발생할 수 있습니다.

`thread_local`의 장단점은 다음과 같습니다.

- 스레드별 데이터는 보통 한 스레드에서만 접근하므로 데이터 레이스에서 안전합니다.
- 표준 C++에서 스레드별 데이터를 만드는 유일한 방법입니다.
- 접근 시 스레드 시작 또는 최초 사용 중 예측하기 어려운 코드가 실행될 수 있습니다.
- 사실상 전역 변수이므로 스레드 안전성 외의 전역 변수 단점을 그대로 가집니다.
- 메모리 사용량은 실행 중인 스레드 수에 비례해 커질 수 있습니다.
- 데이터 멤버는 `static`이 아닌 한 `thread_local`일 수 없습니다.
- 복잡한 소멸자를 가진 `thread_local` 변수는 use-after-free 위험이 큽니다.
- 전역/정적 객체에서 소멸자를 생략해 누수시키는 패턴은 `thread_local`에는 그대로 적용하기 어렵습니다. 스레드가 많이 생성·종료되는 동안 누수가 누적될 수 있기 때문입니다.

---

## 이해하기 쉽게 설명하기

`thread_local`은 "스레드마다 하나씩 있는 전역 변수"에 가깝습니다. 같은 이름을 쓰지만 스레드 A와 스레드 B가 보는 객체는 서로 다릅니다. 그래서 캐시, 임시 버퍼, 스레드별 상태처럼 공유하면 안 되는 데이터를 둘 때 유용합니다.

하지만 전역 변수와 마찬가지로 언제 초기화되고 언제 파괴되는지 추적하기 어렵습니다. 특히 스레드가 끝날 때 여러 `thread_local` 객체가 차례로 파괴되므로, 소멸자에서 다른 `thread_local` 객체를 건드리는 설계는 피해야 합니다.
