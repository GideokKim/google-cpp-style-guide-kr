# 정적 변수와 전역 변수 (Static and Global Variables)

정적 저장 기간을 가진 객체는 사소하게 소멸(trivially destructible)할 수 있는 경우가 아니라면 금지됩니다. 쉽게 말해 소멸자가 실제로 할 일이 없어야 합니다. 더 엄밀하게는 사용자 정의 소멸자나 가상 소멸자가 없고, 모든 기반 클래스와 비정적 멤버도 사소하게 소멸 가능해야 합니다. 함수 지역 정적 변수는 동적 초기화를 사용할 수 있습니다.

네임스페이스 범위 변수나 정적 클래스 멤버 변수의 동적 초기화는 권장되지 않지만, 제한된 상황에서는 허용됩니다. 경험적으로 전역 변수의 선언만 보았을 때 `constexpr`일 수 있다면 이 요구사항을 만족할 가능성이 큽니다.

정적 저장 기간을 가진 객체는 초기화된 시점부터 프로그램 종료까지 살아 있습니다. 여기에는 네임스페이스 범위 변수, 클래스의 정적 데이터 멤버, `static`으로 선언된 함수 지역 변수가 포함됩니다. 함수 지역 정적 변수는 제어가 처음 선언을 지날 때 초기화되고, 그 외 정적 저장 기간 객체는 프로그램 시작 중 초기화됩니다.

동적 초기화는 생성자 호출, 메모리 할당, 현재 프로세스 ID를 읽는 식의 비상수 작업이 초기화 중 일어나는 경우입니다. 정적 초기화는 상수나 0으로 표현되는 값처럼 프로그램 시작 전에 안정적으로 준비될 수 있는 초기화입니다.

전역/정적 변수는 이름 있는 상수, 번역 단위 내부 보조 데이터, 명령줄 플래그, 로깅, 등록 메커니즘 등에서 유용합니다. 그러나 동적 초기화나 사소하지 않은 소멸자를 가진 전역/정적 변수는 초기화 순서와 소멸 순서 문제를 만들 수 있습니다. 번역 단위 사이의 초기화 순서는 보장되지 않고, 소멸도 복잡한 순서 문제를 가집니다.

## 소멸에 대한 결정

소멸자가 사소하면 실제 실행 순서 문제가 없습니다. 그렇지 않으면 수명이 끝난 객체에 접근할 위험이 생깁니다. 그래서 정적 저장 기간 객체는 사소하게 소멸 가능한 경우에만 허용합니다. 기본 타입, 사소하게 소멸 가능한 타입의 배열, `constexpr` 변수는 허용되는 대표적인 예입니다.

```cpp
const int kNum = 10;  // 허용

struct X { int n; };
const X kX[] = {{1}, {2}, {3}};  // 허용

constexpr std::array<int, 3> kArray = {1, 2, 3};  // 허용

const std::string kFoo = "foo";  // 나쁨: 사소하지 않은 소멸자
```

참조는 객체가 아니므로 소멸 가능성 제약의 대상은 아니지만, 동적 초기화 제약은 여전히 적용됩니다. 예를 들어 `static T& t = *new T;` 같은 함수 지역 정적 참조는 허용될 수 있습니다.

## 초기화에 대한 결정

초기화에서는 생성자 실행뿐 아니라 초기화 식 자체가 상수식인지도 고려해야 합니다. 우리가 찾는 개념은 C++ 표준의 상수 초기화입니다. 초기화 식이 상수식이고 생성자를 호출한다면 그 생성자도 `constexpr`이어야 합니다.

상수 초기화는 항상 허용됩니다. 정적 저장 기간 변수의 상수 초기화는 `constexpr` 또는 `constinit`으로 표시하는 것이 좋습니다. 표시되지 않은 비지역 정적 저장 기간 변수는 동적 초기화 가능성이 있다고 보고 매우 신중히 검토해야 합니다.

동적 초기화는 일반적으로 금지되지만, 어떤 프로그램 동작도 다른 초기화와의 순서에 의존하지 않는 경우에는 제한적으로 허용됩니다. 함수 지역 정적 변수의 동적 초기화는 허용되며 흔히 사용됩니다.

## 일반적인 패턴

- 전역 문자열 상수가 필요하면 `string_view`, 문자 배열, 문자 포인터의 `constexpr` 변수를 고려하세요.
- 정적 맵, 집합, 동적 컨테이너는 사소하지 않은 소멸자를 가지므로 피하세요. 작은 고정 컬렉션은 배열과 선형 탐색으로 충분한 경우가 많습니다.
- 스마트 포인터는 소멸 중 정리를 수행하므로 정적 객체로 금지됩니다.
- 직접 정의한 타입의 정적 상수 데이터가 필요하면 사소한 소멸자와 `constexpr` 생성자를 제공하세요.
- 다른 방법이 없다면 함수 지역 정적 포인터나 참조로 동적으로 만든 객체를 의도적으로 해제하지 않는 방식을 사용할 수 있습니다.

## 이해하기 쉽게 설명하기

전역 변수와 정적 변수는 프로그램 전체에 오래 살아서 편리하지만, 바로 그 점 때문에 위험합니다. 특히 "누가 먼저 초기화되는가"와 "누가 먼저 파괴되는가"는 파일이 여러 개로 나뉘면 예상하기 어렵습니다.

안전한 전역 데이터는 보통 단순한 상수입니다. 반대로 `std::string`, `std::map`, 스마트 포인터처럼 생성자와 소멸자가 의미 있는 일을 하는 타입은 프로그램 시작과 종료 시점에 숨어 있는 코드를 실행합니다. 이 숨은 실행이 다른 전역 객체와 얽히면 재현하기 어려운 버그가 됩니다.

따라서 전역으로 둘 값은 가능한 한 `constexpr`/`constinit`으로 표현하고, 복잡한 객체가 꼭 필요하면 함수 안에서 지연 초기화하거나 명시적으로 수명을 관리하는 편이 좋습니다.
