# 런타임 타입 정보 (Run-Time Type Information, RTTI)

런타임 타입 정보(RTTI)는 피하세요. RTTI는 `typeid`나 `dynamic_cast`를 사용해 실행 중인 객체의 실제 C++ 클래스가 무엇인지 묻는 기능입니다.

표준적인 대안은 클래스 계층을 수정하거나 다시 설계해야 할 수 있습니다. 널리 쓰이는 성숙한 코드에서는 그런 변경이 어렵거나 바람직하지 않을 때가 있습니다. 또한 팩토리 테스트에서 새로 만든 객체의 동적 타입을 확인하거나, 객체와 mock 사이의 관계를 관리하는 일부 단위 테스트에서는 RTTI가 유용할 수 있습니다.

하지만 RTTI를 자주 쓰게 된다면 설계가 객체의 추상 인터페이스를 충분히 활용하지 못하고 있다는 신호일 수 있습니다. 객체의 실제 파생 타입을 확인한 뒤 분기하는 코드는 새 파생 타입이 추가될 때마다 다시 수정되어야 하고, 타입 계층의 세부 구현에 호출자가 의존하게 만듭니다.

가능하면 다음 대안을 먼저 고려하세요.

- 필요한 동작을 가상 함수로 노출해 객체가 스스로 올바른 일을 하게 합니다.
- 타입별 처리가 꼭 필요하다면 방문자 패턴이나 명시적인 분류 값을 검토합니다.
- 테스트에서만 필요한 타입 확인은 테스트 코드 안에 제한합니다.
- `dynamic_cast`가 실패할 가능성과 실패 시 동작을 명확히 처리합니다.

RTTI를 사용해야 하는 경우에도 범위를 좁히고, 왜 다형적 인터페이스나 다른 설계가 적절하지 않은지 코드 근처에 설명을 남기는 것이 좋습니다.

---

## 이해하기 쉽게 설명하기

RTTI는 쉽게 말해 객체에게 "너의 진짜 타입이 뭐야?"라고 묻는 기능입니다. 이 질문이 자주 필요하다면, 객체에게 일을 시키는 대신 객체의 내부 분류를 밖에서 해석하고 있다는 뜻일 수 있습니다.

예를 들어 `Shape`가 있다면 호출자가 `Circle`인지 `Rectangle`인지 검사해서 직접 분기하기보다, `Shape::Draw()` 같은 가상 함수를 호출해 각 타입이 자기 일을 하도록 만드는 편이 보통 더 낫습니다. 이렇게 하면 새 도형이 추가되어도 호출자 코드를 덜 고치게 됩니다.

RTTI가 완전히 금지되는 것은 아닙니다. 테스트에서 팩토리가 올바른 타입을 만들었는지 확인하거나, 오래된 클래스 계층을 당장 바꾸기 어려운 경우에는 제한적으로 쓸 수 있습니다. 다만 제품 코드에서 반복적으로 등장한다면 설계를 다시 살펴볼 신호로 받아들이세요.
