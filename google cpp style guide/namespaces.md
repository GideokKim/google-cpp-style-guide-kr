# 네임스페이스 (Namespaces)

몇 가지 예외를 제외하고 코드는 네임스페이스 안에 두세요. 네임스페이스 이름은 프로젝트 이름과 필요하다면 경로를 바탕으로 고유하게 정해야 합니다. `using namespace foo` 같은 using 지시문을 사용하지 말고, 인라인 네임스페이스도 사용하지 마세요. 이름 없는 네임스페이스는 내부 연결 규칙을 따릅니다.

네임스페이스는 전역 범위를 여러 이름 있는 범위로 나눕니다. 그래서 서로 다른 프로젝트가 같은 이름의 클래스나 함수를 갖더라도 충돌하지 않게 해 줍니다. 예를 들어 두 프로젝트가 모두 전역 범위에 `Foo`를 정의하면 충돌할 수 있지만, 각각 `project1::Foo`, `project2::Foo`로 두면 서로 다른 심볼이 됩니다.

인라인 네임스페이스는 이름을 바깥 네임스페이스에 자동으로 노출합니다. 이는 주로 ABI 버전 관리 같은 큰 정책의 일부로 쓰기 위한 기능이며, 일반 코드에서는 이름이 실제로 어디에 선언되었는지 혼란스럽게 만들 수 있습니다.

네임스페이스를 사용할 때는 다음을 지키세요.

- 네임스페이스 이름 규칙을 따릅니다.
- 여러 줄 네임스페이스는 닫는 주석을 남깁니다.
- include, 플래그 선언, 다른 네임스페이스의 전방 선언 뒤에 파일 전체를 네임스페이스로 감쌉니다.
- 생성된 프로토콜 메시지 코드는 `.proto` 파일의 `package` 지정자를 사용해 네임스페이스를 정합니다.
- `std` 네임스페이스 안에 어떤 것도 선언하지 마세요. 표준 라이브러리 심볼은 직접 선언하지 말고 올바른 헤더를 포함하세요.
- using 지시문으로 네임스페이스의 모든 이름을 가져오지 마세요.
- 헤더 파일의 네임스페이스 범위에서 별칭을 만들 때는 공개 API가 되지 않도록 내부 전용 영역에 숨기거나 적절히 이름 붙이세요.
- 새 코드에서는 한 줄 중첩 네임스페이스 선언을 선호할 수 있습니다.

```cpp
namespace my_project::my_component {

class Widget {
 public:
  void Draw();
};

}  // namespace my_project::my_component
```

---

## 이해하기 쉽게 설명하기

네임스페이스는 코드에 성을 붙이는 것과 비슷합니다. `Foo`라는 이름만 있으면 누가 만든 `Foo`인지 헷갈릴 수 있지만, `my_project::Foo`라고 쓰면 소속이 명확해집니다.

`using namespace`는 편해 보이지만 큰 파일이나 헤더에서 쓰면 많은 이름이 한꺼번에 들어와 충돌을 숨깁니다. 특히 헤더에서 이런 편의를 제공하면 그 헤더를 포함한 모든 사용자에게 영향을 줍니다. 그래서 필요한 이름만 명시적으로 쓰거나, 아주 좁은 함수 내부에서만 별칭을 쓰는 편이 안전합니다.
