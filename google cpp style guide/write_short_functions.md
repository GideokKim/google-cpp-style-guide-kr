# 짧은 함수 작성하기 (Write Short Functions)

## 원문 규칙 번역

작고 집중된 기능을 선호합니다.

우리는 긴 함수가 때로는 적절하다는 것을 알고 있으므로 함수 길이에 엄격한 제한을 두지 않습니다. 함수가 40줄 정도를 초과하는 경우, 프로그램 구조를 손상시키지 않고 분할할 수 있는지 생각해 보세요.

긴 기능이 지금 완벽하게 작동하더라도 몇 달 후에 누군가 이를 수정하면 새로운 동작이 추가될 수 있습니다. 이로 인해 찾기 어려운 버그가 발생할 수 있습니다. 함수를 짧고 단순하게 유지하면 다른 사람이 코드를 더 쉽게 읽고 수정할 수 있습니다. 작은 함수는 테스트하기도 더 쉽습니다.

일부 코드를 작업할 때 길고 복잡한 함수를 찾을 수 있습니다. 기존 코드를 수정한다고 해서 겁먹지 마세요. 이러한 함수로 작업하는 것이 어렵다고 판명되거나 오류를 디버그하기 어렵다고 판단되거나 그 일부를 여러 다른 컨텍스트에서 사용하려는 경우 함수를 더 작고 관리하기 쉬운 조각으로 나누는 것을 고려하세요.

---

## 이해하기 쉽게 설명하기

짧은 함수 작성하기 규칙을 적용할 때는 원문 규칙을 문자 그대로 외우기보다, 왜 이 선택이 독자에게 더 명확한지 살펴보면 쉽습니다. 코드 리뷰에서는 이 기능이 호출 지점에서 의도를 숨기지 않는지, 더 단순한 구조로 같은 목적을 달성할 수 없는지, 기존 코드와 섞였을 때 유지보수 비용이 커지지 않는지를 확인하세요.
