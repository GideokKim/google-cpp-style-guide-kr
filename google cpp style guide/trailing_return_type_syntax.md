# 후행 반환 타입 문법 (Trailing Return Type Syntax)

## 원문 규칙 번역

일반 구문(선행 반환 유형)을 사용하는 것이 실용적이지 않거나 읽기 어려운 경우에만 후행 반환 유형을 사용하십시오.

C++에서는 두 가지 다른 형태의 함수 선언을 허용합니다. 이전 형식에서는 반환 유형이 함수 이름 앞에 나타납니다. 예를 들어:

```cpp
int Foo(int x);
```

최신 형식에서는 함수 이름 앞에 auto 키워드를 사용하고 인수 목록 뒤에는 후행 반환 유형을 사용합니다. 예를 들어, 위 선언은 다음과 같이 작성할 수 있습니다.

```cpp
auto Foo(int x) -> int;
```

후행 반환 유형은 함수의 범위에 있습니다. 이는 int와 같은 간단한 경우에는 차이가 없지만 클래스 범위에 선언된 유형이나 함수 매개변수 측면에서 작성된 유형과 같은 더 복잡한 경우에는 중요합니다.

후행 반환 형식은 람다 식의 반환 형식을 명시적으로 지정하는 유일한 방법입니다. 어떤 경우에는 컴파일러가 람다의 반환 유형을 추론할 수 있지만 모든 경우에 그런 것은 아닙니다. 컴파일러가 자동으로 추론할 수 있는 경우에도 때로는 명시적으로 지정하는 것이 독자에게 더 명확할 수 있습니다.

때로는 함수의 매개변수 목록이 이미 표시된 후에 반환 유형을 지정하는 것이 더 쉽고 읽기 쉽습니다. 이는 반환 유형이 템플릿 매개변수에 따라 달라질 때 특히 그렇습니다. 예를 들어:

```cpp
    template <typename T, typename U>
    auto Add(T t, U u) -> decltype(t + u);

```

```cpp
    template <typename T, typename U>
    decltype(declval<T&>() + declval<U&>()) Add(T t, U u);

```

후행 반환 유형 구문은 C 및 Java와 같은 C++ 유사 언어에 유사하지 않으므로 일부 독자에게는 익숙하지 않을 수 있습니다.

기존 코드베이스에는 새 구문을 사용해도 변경되지 않는 엄청난 수의 함수 선언이 있으므로 현실적인 선택은 이전 구문만 사용하거나 둘을 혼합하여 사용하는 것입니다. 단일 버전을 사용하는 것이 스타일의 통일성을 위해 더 좋습니다.

대부분의 경우 반환 유형이 함수 이름 앞에 오는 이전 스타일의 함수 선언을 계속 사용합니다. 필요한 경우(예: 람다) 또는 함수의 매개변수 목록 뒤에 유형을 배치하여 훨씬 더 읽기 쉬운 방식으로 유형을 작성할 수 있는 경우에만 새로운 후행 반환 유형 형식을 사용하십시오. 후자의 경우는 드물다. 이는 대부분 상당히 복잡한 템플릿 코드의 문제이므로 대부분의 경우 권장되지 않습니다.

## 이해하기 쉽게 설명하기

후행 반환 타입 문법 규칙을 적용할 때는 원문 규칙을 문자 그대로 외우기보다, 왜 이 선택이 독자에게 더 명확한지 살펴보면 쉽습니다. 코드 리뷰에서는 이 기능이 호출 지점에서 의도를 숨기지 않는지, 더 단순한 구조로 같은 목적을 달성할 수 없는지, 기존 코드와 섞였을 때 유지보수 비용이 커지지 않는지를 확인하세요.
