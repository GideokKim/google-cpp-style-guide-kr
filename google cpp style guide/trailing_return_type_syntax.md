# 후행 반환 타입 문법 (Trailing Return Type Syntax)

후행 반환 타입은 일반 문법(선행 반환 타입)을 쓰는 것이 실용적이지 않거나 훨씬 읽기 어려운 곳에서만 사용하세요.

**정의:**

C++는 두 가지 형태의 함수 선언을 허용합니다. 오래된 형태에서는 반환 타입이 함수 이름 앞에 옵니다. 예를 들면 다음과 같습니다.

```cpp
int Foo(int x);
```

새로운 형태는 함수 이름 앞에 `auto` 키워드를 쓰고, 인자 목록 뒤에 후행 반환 타입을 씁니다. 예를 들어 위의 선언은 다음과 같이 똑같이 쓸 수 있습니다.

```cpp
auto Foo(int x) -> int;
```

후행 반환 타입은 함수의 스코프 안에 있습니다. `int` 같은 단순한 경우에는 차이가 없지만, 클래스 스코프에 선언된 타입이나 함수 매개변수를 사용해 표현한 타입처럼 더 복잡한 경우에는 중요합니다.

**장점:**

후행 반환 타입은 [람다 표현식](lambda_expressions.md)의 반환 타입을 명시적으로 지정하는 유일한 방법입니다. 컴파일러가 람다의 반환 타입을 추론할 수 있는 경우도 있지만 모든 경우에 그런 것은 아닙니다. 컴파일러가 자동으로 추론할 수 있을 때조차 명시적으로 적어 주는 편이 독자에게 더 명확할 때가 있습니다.

함수의 매개변수 목록이 이미 나온 뒤에 반환 타입을 적는 편이 더 쉽고 읽기 좋을 때도 있습니다. 반환 타입이 템플릿 매개변수에 의존할 때 특히 그렇습니다. 예를 들면 다음과 같습니다.

```cpp
    template <typename T, typename U>
    auto Add(T t, U u) -> decltype(t + u);
```

이것과

```cpp
    template <typename T, typename U>
    decltype(declval<T&>() + declval<U&>()) Add(T t, U u);
```

를 비교해 보세요.

**단점:**

후행 반환 타입 문법은 C나 Java 같은 C++ 계열 언어에는 대응하는 것이 없어서, 어떤 독자에게는 낯설 수 있습니다.

기존 코드베이스에는 새 문법을 쓰도록 바뀌지 않을 함수 선언이 엄청나게 많습니다. 그래서 현실적인 선택지는 옛 문법만 쓰거나 두 가지를 섞어 쓰거나 둘 중 하나입니다. 스타일의 통일성 면에서는 한 가지만 쓰는 편이 낫습니다.

**결정:**

대부분의 경우에는 반환 타입이 함수 이름 앞에 오는 옛 방식의 함수 선언을 계속 쓰세요. 새 후행 반환 타입 형태는 (람다처럼) 반드시 필요한 경우나, 함수의 매개변수 목록 뒤에 타입을 둠으로써 그 타입을 훨씬 읽기 좋게 쓸 수 있는 경우에만 쓰세요. 후자는 드물어야 합니다. 대체로 꽤 복잡한 템플릿 코드에서나 문제가 되는데, 그런 코드는 [대부분의 경우 권장되지 않습니다](template_metaprogramming.md).

## 옮긴이 풀이

### 핵심: 일반(선행) 구문이 어려울 때만 후행 반환 타입

C++에는 두 가지 함수 선언 형식이 있습니다.

```cpp
int Foo(int x);          // 선행 반환 타입 (기본)
auto Foo(int x) -> int;  // 후행 반환 타입
```

기본은 **선행 반환 타입**입니다. 선행 구문이 비실용적이거나 읽기 어려울 때만 후행 형식을 쓰세요.

### 후행 형식이 필요/유용한 경우

- **람다의 반환 타입을 명시**하는 유일한 방법입니다.
- 반환 타입이 **매개변수에 의존**할 때 더 읽기 쉽습니다.

```cpp
template <typename T, typename U>
auto Add(T t, U u) -> decltype(t + u);   // 후행: 매개변수를 이미 본 뒤라 간결

template <typename T, typename U>
decltype(declval<T&>() + declval<U&>()) Add(T t, U u);  // 선행: 장황
```

### 그 외에는 선행을 유지

후행 구문은 C/Java 등에 없어 낯설고, 기존 코드베이스 대부분이 선행 구문입니다. 스타일 일관성을 위해, 람다나 위 같은 복잡한 템플릿 경우가 아니면 선행 구문을 계속 쓰세요.
