# 후행 반환 타입 문법 (Trailing Return Type Syntax)

`후행 반환 타입 문법`은 해당 C++ 기능을 사용할 때 명확성, 안전성, 유지보수성을 함께 판단하라는 규칙입니다. 기능의 존재보다 독자가 비용 없이 의미를 이해할 수 있는지가 더 중요합니다.

다음 원칙을 따르세요:

- 함수는 한 가지 일을 분명하게 수행하고 호출자가 계약을 쉽게 이해할 수 있어야 합니다.
- 입출력, 수명, 오류 가능성은 호출 지점에서 드러나야 합니다.
- 짧고 명확한 함수는 테스트와 리뷰가 쉽습니다.

이 규칙은 새 코드를 작성할 때 우선 적용하고, 기존 코드는 관련 부분을 수정하는 자연스러운 시점에 함께 정리하는 것이 좋습니다. 공개 API나 넓은 범위에 영향을 주는 선택일수록 더 보수적으로 판단하세요.

---

## 이해하기 쉽게 설명하기

쉽게 말해, `후행 반환 타입 문법` 규칙은 독자가 코드를 읽으면서 추측해야 하는 부분을 줄이기 위한 안전장치입니다. 작성자는 배경을 알고 있지만, 리뷰어와 미래의 유지보수자는 이름·선언·형식에 남은 단서만 보고 판단합니다.

점검할 때는 다음 질문을 사용하세요.

- 호출 지점이나 선언만 보고 의도를 이해할 수 있는가?
- 더 좁은 범위나 더 단순한 기능으로 표현할 수 있는가?
- 장기 유지보수자가 숨은 비용을 추적하지 않아도 되는가?

세 질문 중 하나라도 자신 있게 답하기 어렵다면 더 명시적인 표현, 더 작은 범위, 또는 더 단순한 구조를 선택하는 편이 안전합니다.
